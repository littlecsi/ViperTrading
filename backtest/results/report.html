Walk-forward re-derives its zones every 7 days from the trailing 30 days only, so no decision ever sees its own future. All start from 5,000 USDT. What this cannot tell you

  1. One symbol. Every number here is ETHUSDT. Nothing says the ladder transfers.
  2. The simulated bot decides once a minute; the real one polls every second. Inside a bar only open, high, low and close are known, so the detect–settle–reconcile cycle is coarser here than in production.
  3. The intrabar path is unknowable. A bar is treated as one directional sweep and only rungs on the dominant side can fill, so the book can never round-trip against itself within a minute. An earlier version allowed both sides and reported +318% for a month — essentially all of it manufactured by that one assumption.
  4. No order-book depth and no market impact. Fills happen at the rung price in full.
  5. The configured zones were drawn with recent history visible. Over the longer windows that matters less, but it never becomes a forecast. Read walk-forward for that — and note what it did over a year.
  6. The July window was chosen because the long call was right from there. That is selection bias, the same family as look-ahead: it measures execution GIVEN a correct regime call, not the strategy end to end. Read it as "how well does the machinery work once the direction is right", and note that nothing here picks the direction for you.
  7. A stop that never triggers cannot be judged by the run where it never triggered. 1411 looks good here because ETH bottomed at 1504. One path is not a distribution.
  8. Survivorship of the configuration itself. These are the zones that happen to be configured today. Testing the ladder you already chose is not the same as testing the method that chose it.
